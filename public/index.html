1. Symmetric vs. Asymmetric Cryptography

Feature Symmetric (e.g. AES-256-GCM) Asymmetric (e.g. RSA-2048-OAEP / ECC)
Keys Involved 1 Shared Secret Key (Used for both Encrypt & Decrypt) 2 Keys: Public Key (Encrypt) + Private Key (Decrypt)
Execution Speed Extremely Fast (Hardware AES-NI: Gigabytes/sec) Slow (Modular exponentiation: Kilobytes/sec)
Key Distribution Difficult (Requires secure out-of-band channel) Easy (Public key shared freely over public network)
Primary Use Case Bulk data encryption (Files, databases, TLS traffic) Key exchange (Diffie-Hellman), digital signatures, auth
Standard Best Practice Always use AEAD modes (AES-GCM / ChaCha20-Poly1305) Hybrid Encryption: RSA encrypts ephemeral AES key

2. Fast Hashes vs. Slow Key Derivation Functions (KDFs)

Category Fast Hashes (MD5, SHA-256) Slow Password KDFs (bcrypt, Argon2id)
Design Goal Maximum throughput & data integrity Tunable computation cost & memory hardness
GPU Hashrate Billions / second (GPU/ASIC friendly) Thousands / second (Memory bottlenecked)
Salting Requirement Must be manually concatenated if used Automatically embedded in output string modularly
Password Storage Suitability UNSAFE (Critical Vulnerability) RECOMMENDED (OWASP / NIST Standard)
